# 纸样修复批签台

在馆藏纸件修复现场，记录实际取用了哪张纸、哪个纸面、何种旋转，在什么时点得到了合格试补，以及补片贴在了哪里。完工后交付能独立复算的 JSON 证据和按片裁切 CSV。异测量条件的 Lab 不直接比较，而由修复室发布的标定交接单给出分量增减量、来源量程和最大换算误差。内置数据为合成演练记录；阈值不是文物保护作业规范。

## 异测量条件与标定交接单

供纸有时只做过另一种照明条件下的 Lab 测量。`POST /api/handovers` 登记标定交接单，载明来源与目标条件、来源测值各分量的适用闭区间、分量增减量、换算色差与实际色差的最大可能相差，以及在藏品现场哪个版本起生效。同编号新版生效后，旧版只对过去的开样有意义。

预检和开样都以选中纸面的原始测值为准：同条件照常直接比较；异条件只有当每份当时适用的交接单都足以保证色差不超限时才算通过。每份都明确超限报超限、合格与超限依据并存报冲突、无适用单报条件不可比、其余无法确认报证据不足。试补开样时冻结开样时点与全部适用依据；交接单随后更新不影响已开试样完成观察和贴放。封存（format 2）把全部交接单纳入签件，接手人漏列任何一份适用依据都无法通过复算。

## 启动

需要 Python 3.11+，运行不需要安装依赖。服务仅绑定本机 `127.0.0.1`，不适合直接挂到公网。

```bash
python3 -m paperbench --demo --port 8031
```

在浏览器打开 `http://127.0.0.1:8031`。默认使用 `instance/workbench.sqlite3`；可用 `--db` 指定路径。`--demo` 仅在空库加载样例，不会覆盖现场记录；需要重复演练时换一个数据库路径。无样例的空库用「基础登记」先建规则、藏品、批次和纸页。

## 从样例签出首版

1. 打开藏品 `FOL-07` 的 `Z1`。正面 `KOZO-4A` 转 90° 通过预检；反面不同测量条件，色差不可比较。
2. `T1` 已有 0 h 观察。在待观察的展开区填写 24 h 漂移（例如输入 `4`，表示 0.4）及记录，未翘边时保持勾选框为空，提交后试补合格。
3. 基于 `T1` 分别登记 `P1`（取纸 `20 0 36 38`，贴放 `66 55`）和 `P2`（取纸 `36 0 50 14`，贴放 `90 71`）。两片相接而不相交；分别覆盖上横段和右下段。图下可查各片实际坐标。
4. 确认覆盖 `804 / 804 mm²`，点击「确认完工」。在「封存交付」封存当前现场，展开版本后复算或下载。复开时旧补片不会显示为当前覆盖，切过的纸仍保留在实物纸页图上。

## 构建和工作流检查

```bash
python3 -B -m tools.build
python3 -B -m tools.smoke
python3 -B -m tools.handover_test
```

构建检查使用 Node.js 检查 ES module 语法和本地资产入口；Node.js 不参与运行。HTTP 冒烟在临时目录及回环端口走完整流程，支持 `--through <阶段>`，不改本地工作库。`handover_test` 在进程内核验交接单的适用版本、五类色差结论、签件独立复算与漏列/篡改拒绝。单独的测试套件暂缓。

职责边界：`paperbench/` 的 HTTP 入口、事务和记录层与几何、材料、试补、现场状态和封存计算分开；`web/` 使用 HTML、CSS 和浏览器 ES modules，按页面、表单、图形及交付动作拆分；`examples/` 只放合成输入。
