# 纸样修复批签台

在馆藏纸件修复现场，记录实际取用了哪张纸、哪个纸面、何种旋转，在什么时点得到了合格试补，以及补片贴在了哪里。完工后交付能独立复算的 JSON 证据和按片裁切 CSV。内置数据为合成演练记录；阈值不是文物保护作业规范。

## 启动

需要 Python 3.11+，运行不需要安装依赖。服务仅绑定本机 `127.0.0.1`，不适合直接挂到公网。

```bash
python3 -m paperbench --demo --port 8031
```

在浏览器打开 `http://127.0.0.1:8031`。默认使用 `instance/workbench.sqlite3`；可用 `--db` 指定路径。`--demo` 仅在空库加载样例，不会覆盖现场记录；需要重复演练时换一个数据库路径。无样例的空库用「基础登记」先建规则、藏品、批次和纸页。

## 从样例签出首版

1. 打开藏品 `FOL-07` 的 `Z1`。正面 `KOZO-4A` 转 90° 通过预检；反面不同测量条件，色差不可比较。
2. `T1` 已有 0 h 观察。在待观察的展开区填写 24 h 漂移（例如输入 `4`，表示 0.4）及记录，未翘边时保持勾选框为空，提交后试补合格。
3. 基于 `T1` 分别登记 `P1`（取纸 `20 0 36 38`，贴放 `66 55`）和 `P2`（取纸 `36 0 50 14`，贴放 `90 71`）。两片相接而不相交；分别覆盖上横段和右下段。图下可查各片实际坐标。
4. 确认覆盖 `804 / 804 mm²`，点击「确认完工」。在「封存交付」封存当前现场，展开版本后复算或下载。复开时旧补片不会显示为当前覆盖，切过的纸仍保留在实物纸页图上。

## 成组备料、开裁与回执贴补

需要从同一张供纸取多块料时，在「成组备料与开裁回执」按当前修订逐块登记合格试补、源纸矩形和缺口内拟贴位置。整组源纸都可用、且不超出该实物纸页剩余取纸笔数时才一起接受；未结算的承诺和实际裁切各占一笔，同一备料位转已裁仍只占一笔，同一张纸的两面、其他工作单的取样与补片都遵守同一占位。

备料位流程为「已承诺 → 逐块确认开裁 → 交回回执（已裁 / 未裁交回）」。开裁前可整组撤销；开裁时核对原修订与纸批仍有效。已裁回执带唯一编号、永久占位，重送同一份回执只认一次，换编号或改动回执再结算都被拒绝；未动刀交回则释放占位与笔数。贴补时凭已裁回执重新核对修订、试补、纸批和原定缺口位置，成功才增加覆盖并关联该笔实裁，一笔回执只可贴一片。批次停用或缺口复开后，已开裁的料仍可登记回执，已裁位置永不释放。

## 构建和工作流检查

```bash
python3 -B -m tools.build
python3 -B -m tools.smoke
```

构建检查使用 Node.js 检查 ES module 语法和本地资产入口；Node.js 不参与运行。HTTP 冒烟在临时目录及回环端口走完整流程，支持 `--through <阶段>`，不改本地工作库。单独的测试套件暂缓。

职责边界：`paperbench/` 的 HTTP 入口、事务和记录层与几何、材料、试补、现场状态和封存计算分开；`web/` 使用 HTML、CSS 和浏览器 ES modules，按页面、表单、图形及交付动作拆分；`examples/` 只放合成输入。
